# OmniDrop — guide for Claude Code

Local-first desktop file converter: Tauri 2 + React 19/TypeScript + Rust.

## Layout

- `crates/omnidrop-engine` — conversion engine with no UI dependencies. Pipeline: inspector → capability → plan → job → executors → validator → output.
- `crates/omnidrop-app` — settings, history, IPC payloads and thumbnails (the testable part of the shell).
- `src-tauri` — Tauri commands and native integration. It has no tests: test binaries that link the webview runtime cannot start on Windows without an application manifest.
- `src` — React UI. `src/lib/bindings` is generated by `cargo test` (ts-rs); never edit it by hand.
- `docs` — product spec, architecture, formats, design system, privacy and ADRs.

## Commands

```bash
npm run tauri dev                 # run the app
npm run dev                       # UI only, simulated backend (?demo=files|running|done&theme=dark&lang=en)
cargo test --workspace            # engine + app model (regenerates bindings)
npm test && npm run typecheck
cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all --check
```

## Rules

- Paths never come from the UI: use ids and open native dialogs from Rust (ADR 0004).
- Executors only stage results; `OutputManager` publishes after the validator (ADR 0005).
- Processes take argument vectors only, `file:` inputs for FFmpeg, timeouts, and are killed on cancel.
- Offer an operation only when it is implemented, tested and available on the machine.
- Every user-visible string goes in both `src/i18n/pt-BR.ts` and `src/i18n/en.ts`.
- The skills in `.claude/skills/` cover UX, the engine, accessibility, testing and releases.
